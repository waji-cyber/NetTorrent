# NetTorrent — Platform Integration Guide

How NetTorrent plugs into Windows and Android: protocol handlers, share
intents, storage permissions, and startup. Every item below is
**documented, verify at build time** — the native folders (`android/`,
`windows/`) are generated by `flutter create` (see `BUILD.md`), so apply the
snippets after generation and re-apply if you regenerate.

---

## 1. Android

### 1.1 Intent filters (`android/app/src/main/AndroidManifest.xml`)

Add the filters inside the `<activity>` that hosts Flutter
(`android:name=".MainActivity"`, `launchMode="singleTop"` recommended so a
second share reuses the running app instead of launching a copy).

**Open `magnet:` links in NetTorrent:**

```xml
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="magnet" />
</intent-filter>
```

**Open `.torrent` files:**

```xml
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <data android:scheme="file" android:mimeType="application/x-bittorrent" />
    <data android:scheme="content" android:mimeType="application/x-bittorrent" />
</intent-filter>
<!-- Fallback for servers that serve .torrent as octet-stream: -->
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="http" android:host="*" android:pathPattern=".*\\.torrent" />
    <data android:scheme="https" android:host="*" android:pathPattern=".*\\.torrent" />
</intent-filter>
```

**"Share → NetTorrent" from browsers and other apps:**

```xml
<intent-filter>
    <action android:name="android.intent.action.SEND" />
    <category android:name="android.intent.category.DEFAULT" />
    <data android:mimeType="text/plain" />
</intent-filter>
```

> Status: documented, verify at build time.

### 1.2 Wiring the share intent in Dart

Dependency: `receive_sharing_intent: ^1.8.0` (already in `pubspec.yaml`).
In `main.dart` (or an early app-initialisation step):

```dart
// Cold start: was the app opened via Share?
final initial = await ReceiveSharingIntent.getInitialSharedMedia();
for (final file in initial) {
  if (file.type == SharedMediaType.text) handleSharedText(file.path);
}
ReceiveSharingIntent.reset();

// Warm start: app already running, user shares again.
_receiveSub = ReceiveSharingIntent.sharedMediaStream.listen((files) {
  for (final file in files) {
    if (file.type == SharedMediaType.text) handleSharedText(file.path);
  }
});
```

`handleSharedText(text)` should trim the text, then route it:
`magnet:?…` → `TorrentService.addMagnet`, `http(s)://…` →
`DownloadManager.addHttpDownload`, anything else → show "not a supported link".
Remember to cancel the subscription on dispose.

> Status: documented, verify at build time (API verified against
> `receive_sharing_intent` 1.8.x; re-check if the version changes).

### 1.3 Storage and permissions

- **Default download folder:** the app-specific external directory
  (`getExternalStorageDirectory()`), e.g.
  `/storage/emulated/0/Android/data/com.example.nettorrent/files/Download`.
  On Android 10+ this needs **no** storage permission and is removed with the app.
- **Custom folders:** use the system folder picker (Storage Access Framework,
  `ACTION_OPEN_DOCUMENT_TREE` via `file_picker`) — the user grants access to
  exactly the folder they choose. Persist the URI permission across restarts.
- **Permissions** (`permission_handler`): request `Permission.notification`
  for completion alerts; request storage permission only on Android ≤ 10 or when
  the user picks a legacy shared folder, and explain *why* in the rationale
  dialog — never request broad `MANAGE_EXTERNAL_STORAGE` for this project.

> Status: documented, verify at build time (test on a real device; emulators
> hide several scoped-storage edge cases).

## 2. Windows

### 2.1 `magnet://` protocol association

Save as `magnet-protocol.reg` and double-click (writes to `HKEY_CURRENT_USER`,
so **no admin rights needed** — replace the install path with your own):

```reg
Windows Registry Editor Version 5.00

[HKEY_CURRENT_USER\Software\Classes\magnet]
@="URL:Magnet Protocol"
"URL Protocol"=""

[HKEY_CURRENT_USER\Software\Classes\magnet\shell\open\command]
@="\"C:\\NetTorrent\\NetTorrent.exe\" \"%1\""
```

How it works: clicking a `magnet:?…` link anywhere in Windows launches
`NetTorrent.exe` with the magnet URI as its first argument. The Flutter app
must read its launch arguments on startup and route a `magnet:?…` argument to
`TorrentService.addMagnet` (documented, verify at build time).

To undo: delete the `HKEY_CURRENT_USER\Software\Classes\magnet` key.

### 2.2 `.torrent` file association

Two supported routes (documented, verify at build time):

1. **Manual (recommended for the demo):** right-click a `.torrent` file →
   *Open with* → *Choose another app* → select `NetTorrent.exe` → tick
   *Always use this app*. Windows stores the association; no registry editing.
2. **Registry:** create a ProgID under `HKEY_CURRENT_USER\Software\Classes`
   (e.g. `NetTorrent.Torrent`), point its `shell\open\command` at
   `NetTorrent.exe "%1"`, and set
   `HKEY_CURRENT_USER\Software\Classes\.torrent` `(Default)` to that ProgID.

### 2.3 Start with Windows (startup on login)

- **In-app toggle (Settings → Startup):** when enabled, the app writes a value
  under `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`
  pointing at `NetTorrent.exe`. HKCU, so no admin needed in the normal case.
- **Manual alternative:** if registry writes are blocked by policy, use Task
  Scheduler instead: *Create Basic Task* → trigger *When I log on* → action
  *Start a program* → `NetTorrent.exe`. Document this path in the user manual.

> Status: documented, verify at build time. Auto-start registry writes are the
> one spot where a locked-down lab PC may need the Task Scheduler route.

## 3. Honest limits (say these in the demo)

- Android intent filters only *offer* NetTorrent as a handler — the user still
  picks it the first time; nothing is hijacked silently.
- `magnet:` association on Windows needs the `.reg` step (or manual
  Default-Apps choice); it is not automatic on install because this project
  ships a portable zip, not an installer.
- Neither platform can force Google Drive / Chrome / third-party apps to hand
  over their downloads — manual URL paste is always the fallback and is a
  first-class feature, not an afterthought.
